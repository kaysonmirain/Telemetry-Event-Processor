# Telemetry Event Processor

A concurrent Java service for validating, deduplicating, storing, and summarizing real-time simulation telemetry.

## How It Works

The service reads telemetry produced by the Crowd Simulation Engine. Events are validated and deduplicated before a configurable worker pool updates thread-safe region metrics and writes each accepted event through a repository interface. Worker failures are propagated to the caller instead of being silently discarded.

The default repository is in-memory so the project runs with only the JDK. Setting `JDBC_URL`, `DB_USER`, and `DB_PASSWORD` enables the PostgreSQL repository. The included schema uses idempotent event keys, integrity constraints, and indexes for agent timelines and destination analysis.

A small HTTP API exposes health and metrics endpoints using the JDK HTTP server and virtual threads.

## Project Layout

```text
src/main/java/       Event model, processor, repositories, and HTTP API
src/test/java/       Concurrency, validation, and idempotency tests
sql/schema.sql       PostgreSQL operational schema
sql/analytics.sql    Window-function and region-analysis queries
data/                Sample simulation telemetry
```

## Run Locally

Java 21 or newer:

```bash
make test
make run
```

Process telemetry generated by the C++ simulator:

```bash
java -cp out/main com.kaysonmirain.telemetry.Main \
  --input "../Crowd Simulation Engine/results/telemetry.csv" \
  --threads 8
```

Start the API:

```bash
java -cp out/main com.kaysonmirain.telemetry.Main --serve 8080
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/metrics
```

Docker:

```bash
docker build -t telemetry-event-processor .
docker run --rm -p 8080:8080 telemetry-event-processor
```

## PostgreSQL

Apply `sql/schema.sql`, provide a PostgreSQL JDBC driver at runtime, and set:

```text
JDBC_URL=jdbc:postgresql://localhost:5432/telemetry
DB_USER=telemetry
DB_PASSWORD=telemetry
```

## Limitations

The local build intentionally avoids framework dependencies. A production deployment would add a managed event broker, connection pooling, schema migration tooling, backpressure, dead-letter queues, distributed tracing, and authenticated APIs.
